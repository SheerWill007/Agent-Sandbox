Why Agent Sandbox?

Defense-in-depth isolation for AI-generated code execution

Hardware Isolation

Each session runs in a dedicated Firecracker microVM with its own Linux kernel. KVM + Jailer ensure true isolation—no shared kernel, no container escape vectors.

Fast Boot (~90ms)

Cold start from scratch in ~90ms (p50). Snapshot restoration in 1-5ms. Network namespace, veth pair, and iptables setup included. No waiting—instant execution.

Multi-Language Support

Pre-built templates for Node.js 22, Python 3.12, and Go 1.23. Bring your own Dockerfile to create custom environments with any toolchain.

Network Isolation

Per-VM Linux network namespace with dedicated veth pair, TAP device, and iptables egress chains. Full outbound access, zero cross-tenant leakage.

MCP Integration

Native Model Context Protocol server. Connect any MCP-compatible agent (Claude Desktop, Cline, Roo Cline) directly to isolated execution environments.

Auto Cleanup

Ephemeral sessions with 30-minute idle TTL. Automatic VM teardown, jail directory removal, and network namespace reclamation. Orphan recovery on restart.

Three Integration Interfaces

TypeScript SDK

Type-safe client library with async/await API, streaming support, and full filesystem operations.

import { Sandbox } from "@agent-sandbox/sdk";

const sandbox = new Sandbox({ apiKey });
const session = sandbox.create({ 
  template: "python" 
});

const result = await session.runCode(
  "print('Hello VM!')"
);
await session.destroy();

REST API

HTTP/JSON endpoints for session management, command execution, and file operations. Bearer token authentication.

curl -X POST \
  http://localhost:3000/exec/my-session/execute \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "template": "node",
    "command": "node",
    "args": ["--version"]
  }'

Getting Started

From zero to first VM execution in 5 minutes

1

Prerequisites

Ensure you have Linux with KVM, Node.js v20.12+, and Docker installed.

# Check KVM support
ls -l /dev/kvm

# Install Node.js (Ubuntu/Debian)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# Install Docker
curl -fsSL https://get.docker.com | sh
2

Install Firecracker

Download and install Firecracker and Jailer binaries.

ARCH="$(uname -m)"
release_url="https://github.com/firecracker-microvm/firecracker/releases"
latest=$(basename $(curl -fsSLI -o /dev/null -w %{url_effective} ${release_url}/latest))

curl -L ${release_url}/download/${latest}/firecracker-${latest}-${ARCH}.tgz | tar -xz

sudo mv release-${latest}-${ARCH}/firecracker-${latest}-${ARCH} /usr/local/bin/firecracker
sudo mv release-${latest}-${ARCH}/jailer-${latest}-${ARCH} /usr/local/bin/jailer

firecracker --version
3

Install Agent Sandbox

Clone the repository and build environment templates.

git clone https://github.com/SheerWill007/Agent-Sandbox.git
cd Agent-Sandbox/backend
npm install

# Enable IP forwarding
sudo sysctl -w net.ipv4.ip_forward=1

# Create Firecracker user
sudo groupadd -g 982 firecracker 2>/dev/null || true
sudo useradd -u 997 -g 982 -M -s /usr/sbin/nologin firecracker 2>/dev/null || true

# Download kernel
sudo mkdir -p /var/lib/agent-sandbox/artifacts
wget https://github.com/SheerWill007/Agent-Sandbox/releases/download/Beta/vmlinux
sudo mv vmlinux /var/lib/agent-sandbox/artifacts/

# Build templates
sudo ../templates/build.sh node
sudo ../templates/build.sh python
sudo ../templates/build.sh go
4

Start and Test

Create an API key, start the server, and execute your first command.

# Create API key
npm run keys create "my-key"
export SANDBOX_API_KEY="sk_test_..."

# Start server
sudo npm start

# In another terminal, test execution
curl -X POST http://localhost:3000/exec/test-session/execute \
  -H "Authorization: Bearer $SANDBOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"template":"python","command":"python3","args":["--version"]}'

Default limits per microVM:

  • CPU: 1 vCPU, 50% quota (50ms per 100ms period)
  • Memory: 128 MB guest RAM (cgroup-enforced)
  • Disk: 512 MB tmpfs workspace (ephemeral)
  • Processes: 256 max PIDs (fork-bomb protection)
  • Network: Outbound only, optional rate limiting (10 Mbit/s default)

All limits are configurable via environment variables. See Configuration Reference in the docs.

By default, VMs have unrestricted outbound internet access via NAT, except:

  • Cloud metadata endpoint (169.254.169.254) is blocked
  • Cross-tenant communication (10.0.0.0/16) is blocked
  • Host services on 10.0.0.0/16 are blocked

You can configure DNS-based domain filtering (VM_DNS_MODE=allow/deny) or destination IP/port rules (VM_DEST_MODE=allow/deny) for finer control. Bandwidth throttling is also available.
